# 数据可视化系统 · 业务原型 v0.1

> **统一入口**：`../prototype-all/index.html` —— 两个模块共用一个可折叠侧边栏（本页面仍可单独打开）。
> 对应文档：`PRD-数据可视化系统-v0.9.docx`（PRD-VZ-001）
> 用途：把 PRD 里"看数、查数、用数"的逻辑变成可以点的界面。
> 声明：纯前端演示，无后端、无真实数据；机构名、人名、指标值均为虚构。

---

## 1. 怎么打开

双击 `index.html`，用 Edge / Chrome 打开即可，**不需要起服务、不需要安装**。

- 建议窗口宽度 ≥ 1366（原型按 1440 设计）。
- 数据存在浏览器 localStorage，刷新不丢；想恢复初始状态，清一下站点数据即可。
- 按 `Esc` 关闭弹窗 / 抽屉。
- 左侧最下方「基础支撑管理」可以跳回第一个模块原型。

目录结构：

```
prototype-viz/
├─ index.html      外壳（侧边导航 + 顶栏 + 内容区）
├─ styles.css      样式（复用基础支撑原型的视觉体系，追加可视化专用样式）
├─ data-viz.js     演示数据（6 个核心指标、质量波动图、产线、数据表、指标、预警、展示屏、来源关系）
├─ app-viz.js      13 个页面 + 交互逻辑 + 规则校验
└─ README.md       本文件
```

## 2. 和基础支撑是什么关系

**不是同一个系统，是同一个外壳里的两个模块。**

| | 基础支撑管理 | 数据可视化系统 |
|---|---|---|
| 本质 | 能力底座的管理后台 | 数据的消费端 |
| 用户 | 集成方、平台管理员、审计员 | 决策者、业务分析师 |
| 交互 | 表单、审批、监控、留痕 | 逐层查看、一起筛选、拖拽、展示屏 |
| 验收 | 接口调通、权限拦住 | 统计定义一致、时效达标、图表可读 |

两个原型共用一套视觉与组件，但业务逻辑、路由、数据完全独立。基础支撑先做，是因为它的能力目录是可视化的输入。

## 4. 七条演示路径（建议按顺序走）

### ① 经营总览：从"看"到"查"

1. 点「一次合格率」卡片 → 抽屉出现**逐层查看路径**：产品线 → 工序 → 批次。
2. 点「SMT-2」→ 再点「回流焊」→ 最后出现批次明细。
3. 打开右上角「模拟数据延迟」→ 核心指标出现"延迟 2h"，同比变成"—"（BR-VZ-38）。
4. 点右下「产品线贡献」的柱子 → 趋势图跟着一起变，出现"已筛选：SMT-2"；点 × 清除（BR-VZ-30）。

### ② 质量分析：异常不是看一眼

1. 质量波动图上 4 个红点，点任意一个 → 看到**判定规则、发生时间、产品线/工序/批次**。
2. 点「生成异常工单」→ 预警提醒多一条待认领事件。
3. 看缺陷排名：柱状 + 累计占比线 + 80/20 参考线（BR-VZ-45）。

### ③ 生产实时状态：断网会发生什么

1. 打开「模拟断网」→ 顶部出现"数据连接中断 · 最后更新 14:52"，工位全部显示"超时"。
2. 关闭开关 → 自动恢复，不弹配置窗口。
3. 点任意工位 → 看到设备编号、节拍、当班产出、最后心跳。

### ④ 报表制作：业务人员自己出数

1. 点「区域」「产品」加到行维度，点「销售额」加到值。
2. 切「柱状」→ 预览立刻变成柱状图。
3. 「保存为报表」→ 填名称 → 列表里出现草稿；发布需审核（BR-VZ-65）。

### ⑤ 展示屏设计：发布前的三道关

1. 点左侧「指标卡」添加组件 → 右侧属性面板出现。
2. 直接点「发布」→ 被拦：**标题/单位/数据源缺一不可**（BR-VZ-50）。
3. 补上属性 → 保存 → 发布 → 审核通过 → 版本号 +1。
4. 切「3840 × 1080 拼接」→ 画布比例从 16:9 变成 32:9；点「预览」看只读效果（BR-VZ-55）。

### ⑥ 预警提醒：去重、升级、闭环

1. 点「模拟触发」→ 生成一条待认领事件（对象会自动避开已有事件，演示去重逻辑）。
2. 再点两次 → 三个候选对象都占满后，提示"已去重，不重复推送"（BR-VZ-70）。
3. 点「快进 2 小时」→ 未认领的事件打上"已升级"。
4. 认领 → 关闭时必须填**处理措施**，否则不让关。

### ⑦ 来源关系与导出：数据从哪来、能带走到哪

1. 来源关系图点「质量检验明细」→ 抽屉看负责人、数据量、敏感级别。
2. 切「反向（上游）」→ 高亮上游链路；点「模拟上游字段变更」→ 列出 6 个受影响对象。
3. 到「导出审批」：勾敏感字段 + 填理由 → 进入待审批；审批通过后才有水印与下载（BR-VZ-65）。

## 5. 三个约定

1. **每条规则可追**：页面上的 `BR-VZ-xx` 对应 PRD 第 6 章，可在「业务规则清单」逐条确认。
2. **演示数据自洽**：核心指标、质量波动图、批次、事件之间的数字是互相呼应的（如 SMT-2 合格率 91.4%，质量波动图上有对应低点，预警也挂在 SMT-2）。
3. **操作即时生效**：认领、关闭、变更、发布都会改写本地状态，刷新后仍在。

---

## 6. 原型边界（没做的部分）

- 不是最终视觉稿：图表为 SVG/CSS 手绘示意，正式版会接图表库；配色会按 Vben 组件库重做。
- 没有后端：统计定义计算、权限校验在真实系统由服务端完成。
- 未做：真实拖拽缩放、3D 数字孪生、GIS 地图、移动端真机、数据挖掘工作台（PRD 中 P1/P2）。
- 数据仅 12 行销售样例，报表聚合是演示级，不代表真实性能。

## 7. 自测情况

用 Edge 无头浏览器跑了 **77 项自动化检查**，覆盖：

- 13 个路由渲染、无 `undefined/NaN`、无控制台报错；
- 核心指标逐层查看三级、延迟标识、一起筛选与清除；
- 质量波动图上异常点、生成工单；
- 断网降级与恢复、工位详情；
- 单位切换（万元/亿元）、客户脱敏；
- 报表字段添加、图表切换、保存；
- 清洗试跑与启用、数据表详情；
- 指标变更（原因校验、版本 +1）、引用抽屉；
- 展示屏加组件、发布校验、补齐后发布、分辨率切换、预览；
- 预警触发/去重/升级/认领/关闭；
- 来源关系节点、方向切换、影响分析；
- 导出理由校验、敏感审批、水印；
- 规则勾选、问题结论、刷新后状态保持。

结果：**77 passed / 0 failed**。
